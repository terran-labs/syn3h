# Liquid Glass implementations, 19 November 2026

**The first comparison candidate is Shayan’s measured Regular material.** Its web component distinguishes a corner sampling map measured from iOS from the Snell bevel it uses for Clear. That distinction matters for Syn3h, which currently uses one bevel for both. The second candidate is Flutter’s renderer, whose author reports size-dependent transmission, colour lift and rim intensity. Either could outperform ours. Neither has yet beaten the native Mac reference in a controlled comparison here. [Web component and limitations](https://raw.githubusercontent.com/shayann07/liquidglass/main/ports/npm/README.md) · [Flutter measurement changes](https://pub.dev/packages/liquid_glass_renderer/changelog)

## What Apple establishes

Apple demonstrates lensing, interaction, contrast adaptation and shape merging. Its public SwiftUI API lets us render Regular and Clear and opt into interaction. WebKit names several system materials behind a material-hosting feature and a system-appearance setting. The property table describes how WebKit selects a material. It gives no optical kernel, index, sampling distances or compositing curves. Assuming a particular optical model from the demonstration was an inference. [WWDC25 session 219](https://developer.apple.com/videos/play/wwdc2025/219/) · [Materials](https://developer.apple.com/design/human-interface-guidelines/materials.md) · [SwiftUI custom glass](https://developer.apple.com/documentation/swiftui/applying-liquid-glass-to-custom-views.md) · [WebKit property definitions](https://raw.githubusercontent.com/WebKit/WebKit/main/Source/WebCore/css/CSSProperties.json)

**Decision.** Compare observed sampling coordinates on grids and slanted edges, transmission on uniform fields, and state changes over time. Compare the two leading candidates on identical inputs before choosing what to adapt. No third-party code or assets were imported into the runtime for this survey. Keep Apple reference captures local.

## Registered iOS 27 comparison

The 3x iPhone simulator rendered SwiftUI Regular over five backgrounds in both appearances. Each candidate received the exact bare capture and the same 60 point circle and 140 by 48 point pill. The metric averages absolute differences in the encoded eight-bit RGB channels inside each silhouette and gives each of the ten cases equal weight. The top eight points outside the controls matched exactly in every capture. A second independent launch of each native scene gave zero error inside both shapes.

| Renderer | Circle MAE | Pill MAE |
| --- | ---: | ---: |
| Shayan Skia, in-app Regular | 5.07 | 4.19 |
| Flutter Impeller, iOS 27 Regular preset | 38.88 | 39.12 |
| Syn3h Snell prototype | 50.97 | 47.92 |
| liquidGL browser defaults | 56.27 | 56.14 |

Flutter ran in the same simulator with Flutter GPU enabled and its GPU shape widget present. The browser trials used desktop Chromium at scale three. These results rank the tested configurations for resting Regular controls. Safari hardware performance, Clear, press and motion each need their own comparison.

Shayan was closest in each appearance. Light yielded 6.73 and 5.54 for the circle and pill. Dark yielded 3.41 and 2.83. The upstream measured table combines landmark pairs on a Photos toolbar and a Safari lab pill. Syn3h instead measures the phase of a grating through each of its own control sizes. The first inline port using this field scored 8.32 and 8.05. The grid shows remaining wide-blur sampling error, rim differences and displacement at the circle edge.
